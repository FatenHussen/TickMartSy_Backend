# Badges API

## Admin (authenticated)

All badge CRUD operations live under `Route::apiResource('badges', BadgeController::class)` in `routes/api/admin.php`. The controller inherits from `BaseCRUDController`, so pagination, search, and sort query parameters (`search`, `sort_field`, `sort_order`, `page`, `per_page`) work out of the box.

### Create `POST /api/admin/badges`

- **Request body** (`multipart/form-data`):
  - `name.en` (string, required)
  - `name.ar` (string, required)
  - `color` (string, optional)
  - `image` (file `jpeg|jpg|png|gif`, optional)

- `type` is **not** supplied by the client. `BadgeService::create` detects the uploaded file: if the file is a GIF it sets `type = 'gif'`, if any other image is present it sets `type = 'image'`, otherwise it defaults to `'text'`. (`app/Services/Admin/BadgeService.php:24-55`)
- **Response**: `Badge\AdminOneResource` with `id`, translated `name`, `color`, computed `type`, `image` URL, `is_active`, and optional `position`.

### Update `PUT /api/admin/badges/{id}`

- **Request body** is the same as create but every field is optional.
- Uploading a new file will change `type` to `image`/`gif`; omitting the file leaves the stored `type` untouched.
- Response is the same `AdminOneResource`.

### List `GET /api/admin/badges`

- Returns paginated data shaped by `Badge\OneResource` inside a `BaseService` pagination envelope (items + pagination). Each item includes `id`, `name`, `color`, `type`, `image` URL, and pivot `position` when badges are attached elsewhere.

### Show `GET /api/admin/badges/{id}`

- Returns `Badge\AdminOneResource`.

### Delete `DELETE /api/admin/badges/{id}`

- Removes the badge record.

## Users (public-facing)

There is no standalone “badges” endpoint for users. Badges appear inside other resources (products, vendors, baskets, shops, recipes, etc.) under `top_badges`/`bottom_badges` arrays. Those arrays are populated with `Badge\OneResource` objects via the various list/detail resources in `app/Http/Resources/*` (see e.g. `Product\OneResource`, `Basket\OneResource`, `Store\OneResource`, `Vendor\OneResource`, `Recipe\AllResource`, etc.).

Each badge object returned to users follows this shape:

```json
{
  "id": 123,
  "name": {
    "en": "New",
    "ar": "ط§ط¬ظ…ط§ظ" (translated text)
  },
  "color": "success",
  "type": "image",
  "image": "https://.../storage/badges/...",
  "position": "top"
}
```

- `type` continues to reflect the backend-detected value (`text`, `image`, or `gif`).
- `image` is generated by the model’s `getImageUrlAttribute()` and may be `null` for text-only badges.

Badges may be returned with a `position` (e.g., `top` or `bottom`) when they come through pivot relationships, otherwise `position` is `null`.
