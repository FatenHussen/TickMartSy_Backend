# Web Frontend — التسجيل بدون إيميل

الإيميل صار **اختياري** بشاشة التسجيل، ورقم الهاتف صار **مطلوب دايماً**.

قبل، كان لازم واحد من الاثنين (`phone` أو `email`) — يعني كان ممكن حساب بإيميل فقط. هلق الهاتف هو الهوية الأساسية للحساب، والإيميل حقل إضافي.

> المسار: `POST /api/user/auth/register` — مو محمي بتوكن.

---

## 1) شنو تغيّر

| الحقل | قبل | بعد |
|---|---|---|
| `phone` | مطلوب إذا ما في إيميل | **مطلوب دايماً** |
| `email` | مطلوب إذا ما في هاتف | **اختياري** — أرسله أو لا |
| كود التحقق (OTP) | يوصل SMS أو إيميل حسب اللي أرسلته | **SMS دايماً** على `phone` |
| التحقق من حساب موجود | على الحقل اللي أرسلته | على `phone` |

الإيميل إذا أرسلته يتخزن بالحساب لكن **غير موثّق** (`email_verified_at = null`). التوثيق بعد التسجيل يصير على الهاتف فقط.

---

## 2) Endpoint

### `POST /api/user/auth/register`

**Body:**

```json
{
  "name": "أحمد محمد",
  "phone": "0501234567",
  "email": "ahmad@example.com",
  "password": "Passw0rd!",
  "city_id": 1,
  "governorate_id": 1
}
```

بدون إيميل — صحيح تماماً:

```json
{
  "name": "أحمد محمد",
  "phone": "0501234567",
  "password": "Passw0rd!",
  "city_id": 1,
  "governorate_id": 1
}
```

**Response (200):**

```json
{
  "status": true,
  "message": "Success",
  "data": []
}
```

`data` فاضية وما في توكن. بعد نجاح التسجيل روح مباشرة على شاشة إدخال كود OTP.

---

## 3) قواعد التحقق

| الحقل | القاعدة |
|---|---|
| `name` | مطلوب، نص |
| `phone` | **مطلوب**، أرقام فقط (`/^\d+$/`) — بدون `+` وبدون مسافات أو شرطات |
| `email` | اختياري، لكن إذا أرسلته لازم يكون إيميل صحيح |
| `password` | مطلوب، 8 أحرف على الأقل + حرف صغير + حرف كبير + رقم + رمز |
| `city_id` | مطلوب، موجود بجدول المدن |
| `governorate_id` | مطلوب، موجود بجدول المحافظات |

**مهم بالنسبة للإيميل:** لا ترسل `email: ""` (سلسلة فاضية). الـ validation بيرفضها لأنها مو إيميل صحيح. إذا اليوزر ترك الحقل فاضي: احذف المفتاح من الـ payload أو أرسل `null`.

```js
const payload = {
  name,
  phone: phone.replace(/[^\d]/g, ""),
  password,
  city_id: cityId,
  governorate_id: governorateId,
};

if (email.trim()) {
  payload.email = email.trim();
}

await api.post("/api/user/auth/register", payload);
```

### شكل الخطأ (422)

خطأ واحد فقط بكل مرة:

```json
{
  "error": "The phone field is required."
}
```

اعرض `response.data.error` كما هو. ما في كائن `errors` لكل حقل، فما تبني عليه.

---

## 4) الفورم

- خلي حقل الهاتف أول حقل تواصل وعليه `*`.
- احذف `*` والـ `required` من حقل الإيميل، وضيف label زي "الإيميل (اختياري)".
- احذف أي منطق قديم نوع "لازم إيميل أو هاتف" أو tabs/toggle بين "تسجيل بإيميل" و"تسجيل بهاتف" — ما بقى له معنى بالتسجيل.
- validation الإيميل بالواجهة: تحقق من الصيغة **فقط إذا** الحقل مو فاضي.

```js
const emailError = email.trim() && !/^\S+@\S+\.\S+$/.test(email.trim())
  ? "إيميل غير صحيح"
  : null;
```

---

## 5) بعد التسجيل — التحقق

الكود يوصل **SMS على الهاتف**، مهما كان اليوزر أرسل إيميل أو لا.

```http
POST /api/user/auth/verify-otp
```

```json
{
  "phone": "0501234567",
  "code": "12345"
}
```

**Response:**

```json
{
  "status": true,
  "message": "Success",
  "data": {
    "user": {
      "id": 12,
      "name": "أحمد محمد",
      "phone": "0501234567",
      "addresses": [],
      "is_subscription": false,
      "affiliate": { "is_affiliate": false, "approved": false },
      "currency": null
    },
    "token": "12|xxxxxxxx"
  }
}
```

- خزّن `data.token` وكمّل للتطبيق.
- **انتبه:** كائن `user` يرجّع مفتاح `phone` **أو** `email` — مو الاثنين. بما إن كل الحسابات الجديدة عندها هاتف، بترجع `phone` دايماً حتى لو اليوزر سجّل بإيميل كمان. لا تقرأ `data.user.email` من هنا؛ استخدم `GET /api/user/auth/profile` للبيانات الكاملة.
- شاشة "أرسلنا الكود على إيميلك" لازم تنحذف من مسار التسجيل. النص صار: "أرسلنا الكود على رقم هاتفك".
- إعادة الإرسال: نفس الشي بـ `phone`.

إذا اليوزر حاول يعمل login قبل التوثيق، الباك اند يرسل كود جديد ويرجّع خطأ التحقق → ودّيه على شاشة OTP.

---

## 6) تسجيل الدخول — ما تغيّر

`POST /api/user/auth/login` بعده يقبل `phone` أو `email` مع الباسورد. اليوزر اللي عنده إيميل مخزن بيقدر يستخدمه للدخول.

بس انتبه: حساب سجّل بدون إيميل ما بيقدر يستخدم "نسيت كلمة السر" عن طريق الإيميل. خلي الافتراضي بشاشة استعادة الباسورد (`POST /api/user/auth/send-password` بعدها `verify-password`) هو **الهاتف**، والإيميل خيار ثاني.

---

## 7) Do / don't

- **Do:** الهاتف مطلوب وأرقام فقط.
- **Do:** احذف مفتاح `email` كامل إذا فاضي.
- **Do:** بعد التسجيل روح على OTP بالهاتف.
- **Don't:** ما ترسل `email: ""`.
- **Don't:** ما تمنع اليوزر من إكمال التسجيل لأنه ما كتب إيميل.
- **Don't:** ما تعتمد على الإيميل كمعرّف للحساب — ممكن يكون فاضي وممكن يتكرر بين حسابات.
- **Don't:** ما تعرض الإيميل كـ "موثّق" بعد التسجيل.

---

## 8) Checklist

- [ ] حقل الهاتف مطلوب + تنظيف الأرقام قبل الإرسال
- [ ] حقل الإيميل بدون `required`، label فيه "(اختياري)"
- [ ] الإيميل الفاضي ما يتم إرساله بالـ payload
- [ ] validation الإيميل بالواجهة يشتغل فقط لما يكون فيه قيمة
- [ ] حذف منطق/واجهة "إيميل أو هاتف"
- [ ] زر التسجيل ينفتح للـ submit بدون إيميل
- [ ] بعد التسجيل → شاشة OTP بالهاتف مع نص صحيح
- [ ] `verify-otp` ينرسل بـ `phone`
- [ ] رسالة الخطأ من `error` بشكل مباشر
- [ ] شاشة الملف الشخصي تتعامل مع `email = null`

### ما تلمسه

- شاشات الدخول والباسورد (بعدها تقبل الإيميل أو الهاتف)
- تحديث الإيميل من الملف الشخصي (بعده OTP على الإيميل)
- تسجيل التاجر `seller-register` — الإيميل هناك بعده **مطلوب**

## 9) ملاحظات

- `users.email` بقاعدة البيانات nullable وبدون قيد unique، فما تفترض إنه فريد.
- الإيميل بالـ profile response ممكن يجي `null` — عالج هذا بكل مكان يعرض الإيميل.
- توثيق أو إضافة الإيميل بعد التسجيل يصير من الملف الشخصي: `POST /api/user/auth/profile/update_email` وبعدها `POST /api/user/auth/profile/verify` بالكود اللي وصل الإيميل.
