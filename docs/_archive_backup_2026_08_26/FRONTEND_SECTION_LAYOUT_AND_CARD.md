# تخطيط القسم وشكل الكارد (`layout` + `variant`)

توضيح للداشبورد والويب/الموبايل بعد فصل المعنيين اللي كانوا مخلوطين في حقل واحد.

---

## الحقول الثلاثة (لا تخلطوا بينها)

| الحقل | المعنى | القيم | مين يختاره |
|-------|--------|-------|------------|
| **`layout`** | طريقة عرض **القسم كامل** | `slider` \| `list` \| `grid` | الأدمن (خطوة مستقلة) |
| **`variant`** | شكل **الكارد داخل** القسم | `horizontal` \| `vertical` \| `square` | الأدمن (خطوة بعد `layout`) |
| **`display_type_id`** | نوع **المحتوى** (بانر/منتج/متجر...) | أرقام ثابتة من `display_types` | عادة تلقائي من الباك إند |

### `layout` — طريقة عرض القسم

| القيمة | عربي | السلوك |
|--------|------|--------|
| `slider` | سلايدر عرضي | تمرير أفقي يمين/يسار (الافتراضي) |
| `list` | ليستا | عناصر تحت بعض عمودياً |
| `grid` | شبكة | شبكة ثابتة (مثلاً 2×2) |

### `variant` — شكل الكارد

| القيمة | عربي | الاستخدام |
|--------|------|-----------|
| `horizontal` | عرضي | كارد عريض |
| `vertical` | طولي | كارد رأسي (منتج غالباً) |
| `square` | مربع | كارد مربع (فئة غالباً) |

---

## ترتيب العملية في الداشبورد

على `/sections/pages/{id}/sections/create`:

1. **نوع القسم** (بانر / منتجات / متاجر...)
2. **`layout`** — طريقة عرض القسم (سلايدر / ليستا / شبكة) ← الأيقونات اللي عندكم حالياً
3. **`variant`** — شكل الكارد جوا (عرضي / طولي / مربع) ← خطوة جديدة أو حقل ثاني
4. ألوان (اختياري)
5. إرسال

### Payload مثال

```http
POST /api/admin/pages/{pageId}/sections
```

```json
{
  "section_id": 38,
  "layout": "slider",
  "variant": "vertical"
}
```

إنشاء مباشر:

```json
{
  "type": "api",
  "api_method": "products",
  "name": { "ar": "جديد", "en": "New" },
  "filters": { "type": "new", "category_id": 2 },
  "layout": "slider",
  "variant": "vertical"
}
```

تعديل لاحقاً:

```http
PUT /api/admin/page-sections/{id}
```

```json
{
  "layout": "grid",
  "variant": "square"
}
```

### ملاحظات داشبورد

- الخطوة اللي عنوانها خطأ «شكل الكارد» واللي أيقوناتها سلايدر/ليست/شبكة → لازم تصير عنوانها **«طريقة عرض القسم»** وترسل `layout`.
- أضيفوا خطوة/حقل منفصل **«شكل الكارد»** يرسل `variant`.
- لا تستخدموا `display-types` لشكل الكارد ولا لتخطيط القسم.
- لا ترسلوا `display_type_id` إلا إذا عندكم UI مخصص لنوع المحتوى؛ الباك إند يحلّه تلقائياً.

## الويب / الموبايل — كيف تعرضوا

من استجابة القسم (مثلاً `GET /api/user/sections?page_slug=...` أو صفحة الفئة):

```json
{
  "id": 10,
  "layout": "slider",
  "variant": "vertical",
  "display_type_id": 2,
  "items": [ ... ]
}
```

1. اقرأوا **`layout`** أولاً → اختاروا مكوّن القسم:
   - `slider` → سلايدر أفقي
   - `list` → قائمة عمودية
   - `grid` → شبكة
2. داخل المكوّن، اعرضوا كل item بكارد حسب **`variant`**.
3. `display_type_id` اختياري لتوحيد نوع المحتوى (منتج/بانر...) إن احتجتم.

### Fallback للتوافق

إذا وصل قسم قديم بدون `layout` (أو `null`): اعتبروه `slider`.

---

## ما تغيّر في الباك إند

- حقل جديد: `layout` على `sections` و `page_sections` (افتراضي `slider`).
- `variant` بقي لشكل الكارد فقط.
- الـ resources ترجع الحقلين معاً في admin + user APIs.
