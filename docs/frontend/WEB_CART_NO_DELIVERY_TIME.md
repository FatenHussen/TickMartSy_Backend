تدفق السلة / الدفع **صفحتان (أو خطوتان)**.  
**ما في أي ذكر لمدة التوصيل (`delivery_time`) داخل السلة.**

`delivery_time` يبقى على **صفحة المنتج** فقط (وبعد إنشاء الطلب على عناصر الطلب إن لزم).

## 1) القاعدة

| المكان | مدة التوصيل |
|--------|-------------|
| صفحة المنتج | ✅ اعرضوا `product.delivery_time` إن وُجد |
| خطوة السلة 1 (منتجات + فاتورة + دفع + كوبون) | ❌ لا |
| خطوة السلة 2 (ملخص + تأكيد) | ❌ لا |
| `GET /api/user/cart` | ❌ الحقل غير موجود على عناصر السلة |

لا تضيفوا سطر «التسليم خلال…» ولا عمود وقت توصيل في جدول السلة أو الفاتورة.

---

## 2) الخطوتان

### الخطوة 1 — السلة / الدفع

- قائمة المنتجات (كمية، ملاحظة، سعر)
- تفاصيل الفاتورة (مجموع، توصيل، خصم، …)
- اختيار طريقة الدفع
- الكوبون

### الخطوة 2 — الملخص

- ملخص الطلب فقط
- زر التأكيد

**لا** مدة توصيل في أي من الخطوتين.

---

## 3) أين يظهر `delivery_time`

```jsx
{/* صفحة المنتج فقط */}
{product.delivery_time && (
  <p>التسليم: {product.delivery_time}</p>
)}
```

- مرة واحدة على المنتج — **ليس** per variant.
- في السلة: لا تعرضوا الحقل حتى لو كان المنتج مخزّناً من صفحة التفاصيل.

---

## 4) الـ API

```http
GET /api/user/cart
```

عناصر السلة: `id`, `shop_product_variant_id`, `quantity`, `note`, `product.name`, …  
**بدون** `delivery_time`.

```http
GET /api/user/products/{id}
```

```json
{
  "delivery_time": "3-5 أيام"
}
```

بعد الطلب: `delivery_time` قد يظهر على عناصر الطلب — مو على شاشات السلة قبل التأكيد.

---

## 5) غلط vs صح

**غلط**

```jsx
// في Cart / CheckoutSummary
<p>التسليم: {item.product?.delivery_time}</p>
<tr><td>مدة التوصيل</td><td>{range}</td></tr>
```

**صح**

```jsx
// Cart: منتجات + فاتورة + دفع + كوبون → ثم ملخص + تأكيد
// delivery_time فقط في Product page
```

## 6) Checklist

- [ ] خطوة 1: منتجات + فاتورة + دفع + كوبون — بلا مدة توصيل
- [ ] خطوة 2: ملخص + تأكيد — بلا مدة توصيل
- [ ] `delivery_time` معروض على صفحة المنتج فقط
- [ ] لا تعتمدوا على `cart` لإرجاع `delivery_time`
- [ ] لا صف «التسليم» داخل ملخص الفاتورة في السلة
