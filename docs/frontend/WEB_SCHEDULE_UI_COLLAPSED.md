السبب: انبنى أكبر من الحاجة بعد سوء فهم عن السلال المجدولة.  
**ما نلغي الميزة** — نخليها خلف زر لمن يحب يستخدمها.

## 1) القاعدة

| الحالة | ماذا يظهر |
|--------|-----------|
| افتراضي عند فتح السلة / الدفع / تأكيد السلة المخصصة | سطر نص + زر فقط |
| بعد ضغط «عرض تفاصيل الجدولة» | نفس واجهة الجدولة الحالية (مرة واحدة / دوري + تاريخ…) |
| إخفاء مرة ثانية (اختياري) | زر «إخفاء تفاصيل الجدولة» أو طيّ |

لا تفتحوا التقويم ولا كروت «طلب لمرة واحدة / جدولة التوصيل» تلقائياً.

---

## 2) الحالة الافتراضية (مطوي)

سطر واحد بجانب زر:

| العنصر | النص المقترح (عربي) |
|--------|----------------------|
| النص | هل ترغب بجدولة موعد التسليم أو اختيار موعد تسليم دوري؟ |
| الزر | عرض تفاصيل الجدولة |

إنجليزي مقترح:

| العنصر | النص |
|--------|------|
| النص | Want to schedule delivery or set a recurring delivery? |
| الزر | Show scheduling details |

المساحة: سطر (أو صف) واحد فوق الكوبون / زر المتابعة — **مو** بلوك كبير.

الافتراضي المنطقي للطلب: **مرة واحدة** (`confirm_schedule: false`) طالما المستخدم ما فتح التفاصيل واختار جدولة.

---

## 3) بعد الضغط (مفتوح)

اعرضوا الواجهة الموجودة كما هي:

- اختيار: طلب لمرة واحدة · جدولة التوصيل
- تكرار / تاريخ البداية / ملخص / تقويم (إن وُجد)
- نفس سلوك التأكيد السابق

عند الاختيار **جدولة** + تأكيد:

```json
{ "confirm_schedule": true, "start_date": "2026-09-08" }
```

عند **مرة واحدة** أو بدون فتح التفاصيل:

```json
{ "confirm_schedule": false }
```

---

## 4) الـ API — بدون تغيير

لا طلبات جديدة. نفس:

```http
POST /api/user/schedules/{id}/custom-basket/confirm
```

| الاختيار | Body |
|----------|------|
| جدولة دورية | `{ "confirm_schedule": true, "start_date": "…" }` — `start_date` ≥ اليوم |
| مرة واحدة | `{ "confirm_schedule": false }` |

التفاصيل: [`WEB_CUSTOM_BASKET.md`](./WEB_CUSTOM_BASKET.md).

---

## 5) غلط vs صح

| غلط ❌ | صح ✅ |
|--------|--------|
| قسم «تكرار هذه السلة؟» مفتوح دائماً مع تقويم كبير | سطر + زر؛ التفاصيل بعد الضغط فقط |
| إلغاء ميزة الجدولة بالكامل | الميزة موجودة خلف الزر |
| فتح التفاصيل تلقائياً إذا كان في مسودة مجدولة | يبقى مطوي إلا إذا ضغط المستخدم (أو إن حفظتم اختياره صريحاً سابقاً) |

---

## 6) Checklist

- [ ] الحالة الافتراضية = سطر نص + زر «عرض تفاصيل الجدولة»
- [ ] لا تقويم ولا كروت تكرار ظاهرة قبل الضغط
- [ ] بعد الضغط = نفس واجهة الجدولة السابقة
- [ ] بدون فتح التفاصيل → مسار مرة واحدة (`confirm_schedule: false`)
- [ ] عقد الـ API كما هو — لا تغيير باك
