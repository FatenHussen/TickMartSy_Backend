> **أرسلوا هذا الملف لفريق الداشبورد.**

> Base: `/api/admin` + Admin token

حقل **الدرجة** على `categories/attributes/update/{id}` اختياري. يمكن حفظ اسم اللون من دون اختيار درجة. الموقع والتطبيق يلوّنان من `hex` فقط، فإذا ما في ربط تبقى الدائرة رمادية `rgb(161, 161, 170)`.

إذا اختُيرت درجة، تُحفظ في جدول `colors` عبر `POST /api/admin/colors`، ثم تحديث المتغير يرسل `color_id`. ما في مسار جديد.

## 1) القاعدة

صفة اللون هي:

- `type = color`، أو
- اسمها واحد من: `Color` / `colour` / `اللون` / `لون` / `الالوان` / `الألوان` / `الوان` / `ألوان`

حتى لو النوع المحفوظ `square`. لا تعيدوا كتابة `type`.

| الحقل | المعنى |
|--------|--------|
| `values[].id` | رقم قيمة الصفة. يبقى على المتغيّرات. هو `options[].id` عند المستخدم |
| `color_id` | رقم صف في `colors`. اختياري. مو رقم قيمة الصفة |
| `colors.hex` | لون الدائرة `#RRGGBB`. المصدر الوحيد للعرض |
| `shop_variants[].id` | رقم السلة. مو رقم اللون |

من دون `color_id` يُحفظ الاسم (مثل `2` أو `7`) و`hex` يبقى `null`. إعادة حفظ المنتج بلا تغيير القيمة لا تلوّن الدائرة.

`color_id` المرسل يجب أن يكون صفاً موجوداً في `colors`. رقم غير موجود يُرفض (`values.N.color_id`).

إغفال `values` أو إرسالها `[]` عند **إنشاء** صفة لون يربط لوحة `colors` كاملة، وكل صف فيها معه `color_id`.  
ترك `values` خارج طلب **التعديل** لا يعيد كتابة القيم الحالية.  
إغفال `color_id` على صف موجود لا يمسح الربط السابق. الربط يتغيّر فقط إذا أُرسل رقم جديد.

## 2) درجة المتغير

على `categories/attributes/create` و`categories/attributes/update/{id}` مربع الدرجة يفتح نفس باليت إضافة اللون (`/colors/create`): مربع وقوس الألوان.

الدرجة **اختيارية**. إغلاق الباليت من دون درجة جديدة لا يمنع تحديث المتغير.

عند الإغلاق بعد درجة جديدة:

1. إذا الرمز موجود في جدول الألوان، اربطوا `colors.id` الموجود. لا تنشئوا صفاً مكرراً.
2. وإلا أرسلوا الاسم المكتوب على القيمة مع الرمز:

```http
POST /api/admin/colors
```

```json
{
  "name": { "en": "Light Nude Pink", "ar": "وردي نيود فاتح" },
  "hex": "#FDD0DB",
  "is_active": true
}
```

`hex` بصيغة `#RRGGBB`، يُحفظ أحرف كبيرة، وفريد. الاسم للعرض. إذا إحدى اللغتين فاضية انسخوا المملوءة إلى الفارغة قبل الإرسال.

الرد:

```json
{
  "status": true,
  "data": { "id": 31, "hex": "#FDD0DB" }
}
```

ضعوا `data.id` في `color_id` على صف القيمة، ثم اضغطوا **تحديث المتغير** حتى يُرسل الرقم على:

```http
PUT /api/admin/category-attributes/{id}
```

اللون يظهر في `/colors` من طريقين: درجة المتغير، أو إنشاء مباشر على `/colors/create`.

## 3) حفظ قيمة الصفة

```http
POST /api/admin/category-attributes
PUT  /api/admin/category-attributes/{id}
```

باسم فقط، والدرجة لاحقاً:

```json
{
  "category_id": 8,
  "name": { "en": "Color", "ar": "اللون" },
  "type": "color",
  "values": [{
    "id": 160,
    "name": { "en": "2", "ar": "2" }
  }]
}
```

بعد اختيار درجة:

```json
{
  "values": [{
    "id": 160,
    "name": { "en": "2", "ar": "2" },
    "color_id": 31
  }]
}
```

- أرسلوا `values[].id` عند التعديل حتى يبقى نفس الصف.
- `GET /api/admin/category-attributes` و`GET /api/admin/category-attributes/{id}` يرجعان `color_id` و`hex` لصفة اللون.

## 4) فورم المنتج

على `products/update/{id}` مربع الدرجة في صف المتغير هو نفس باليت الألوان. عند الإغلاق بعد درجة جديدة:

1. إذا `hex` موجود في `colors` يُستخدم نفس `colors.id`.
2. وإلا `POST /api/admin/colors` بالاسم والرمز و`is_active: true`. الرد `data.id`.
3. قيمة صفة اللون تُربط بهذا `color_id` عبر `PUT /api/admin/category-attributes/{id}` (القيم الحالية تُرسل مع `id` حتى لا تُستبدل).
4. المتغير يُحفظ بـ `attributes_values_ids` = رقم **قيمة الصفة**، مو رقم اللون.

رقم غير موجود في `attribute_values` يُرفض (`variants.N.attributes_values_ids.0`). بعد اختيار الدرجة يُستبدل الرقم المحذوف برقم القيمة الجديدة.

لا تُضاف قوائم أسماء في الكود لباقي الكتالوج. قائمة المناكير كانت ترقيعاً لذلك المنتج فقط.

---

## 5) شو يشوف المستخدم

`GET /api/user/products/{id}` و`GET /api/user/categories/{id}/attributes` ينسخان `colors.hex` إلى:

- `attributes_map[].options[].hex`
- `shop_variants[].attributes[].hex` لنفس رقم الخيار
- `values[].hex` في صفات الفئة

`Accept-Language` يغيّر الاسم فقط. `hex` ثابت. رد المستخدم ما فيه `color_id`.
